# 요구사항 정의서 v2.0 (2026-11-12)

요구사항 정의서는 프로젝트에서 구현해야 하는 기능과 조건을 정리한 문서이다.
"무엇을 만들 것인가"를 팀원들이 같은 기준으로 이해하기 위해 작성한다.

- 기준: **[화면설계서 최종본 v2.0](틈틈%20화면설계서.md)** (결정 9건 확정, 외부 API 연동 가이드 반영)
  - 추천 흐름: HOM-01 → CON-01 ↔ CON-02 → RES-01 → DET-01 → DET-02 / DET-03
  - 탐색 흐름: HOM-01 → HOM-02 → DET-01 (장소 1곳짜리 상세. 홈 검색 결과도 같음)
  - 저장 흐름: DET-01 → (비로그인) AUT-01 → 복귀 후 저장 → MY-02 → MY-03 → DET-02
  - 회원 흐름: HOM-01 하단바 → MY-01 → MY-02 / MY-04
- 담당은 `AGENTS.md` 3장 역할 분담을 따른다. `BE` 백엔드, `FE` 프론트 화면
- 변경 내역은 맨 아래 [6. 변경 이력](#6-변경-이력) 참고

| REQ-011 | 이동 수단 설정 | 사용자는 대중교통(기본), 도보, 차량 중 하나를 선택할 수 있다. (자전거 제외) | P0 | 정종일 |

| REQ-015 | 주변 장소 검색 | 시스템은 사용자의 출발 위치를 기준으로 일정 반경 내 장소를 조회한다 (카카오 로컬). 맞는 코스가 없으면 반경을 넓혀 다시 찾는다. | P0 | 정종일 |

| REQ-018 | 장소 운영시간 확인 | 시스템은 운영시간 정보가 제공되는 경우 예상 방문 시각의 영업 여부를 확인하여 추천에 반영한다. | P1 | 정종일, 나혜빈 |
| REQ-051 | 주변 장소 탐색 (HOM-02) | 사용자는 조건 없이 현재 위치 주변 장소를 지도와 바텀시트 목록으로 볼 수 있다. 시트는 반만 / 전체 / 내리기 3단계이고, 반경(500m / 1km / 3km, 기본 1km)과 대분류 필터(전체 + 8개)를 고를 수 있다. 장소 카드(썸네일, 이름, 대분류, 거리)를 누르면 장소 1곳짜리 상세로, 마커를 누르면 목록에서 해당 카드를 강조한다. | P0 | 유지수(FE), 정종일(BE) |
| REQ-052 | 홈 장소 검색 | 사용자는 홈 검색창에서 장소·주소를 검색할 수 있다 (카카오 로컬 키워드·주소 검색). 결과는 아래 시트에 목록으로 먼저 보여주고, 선택하면 지도가 이동하며 장소 상세로 연결된다. (결정 7) | P0 | 정종일 |

## 5. 작성 시 주의사항

- 요구사항은 "무엇을 할 수 있어야 하는가" 중심으로 작성한다.
- 구현 방법이나 코드 구조는 요구사항 정의서에 자세히 적지 않는다.
- 요구사항 ID는 API 명세서, 화면 설계서, 테스트 시나리오와 연결할 수 있도록 유지한다. 삭제한 요구사항도 ID를 재사용하지 않는다. (REQ-014 는 원본부터 비어 있음)
- 우선순위가 P0인 기능부터 구현한다.
- 프로젝트 중 요구사항이 변경되면 변경된 내용을 문서에 반영한다.
